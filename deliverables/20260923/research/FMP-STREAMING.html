FMP streaming — what it offers, what we tested, how it would feed the quotes

Research deliverable · 2026-09-23 · nothing deployed, nothing changed in production

“I'm pretty sure there's FMP streaming too. Why are we not using FMP streaming?”

Short answer: FMP does have streaming, and the socket answers from here. Whether our key is entitled to it, and whether it carries the three macro instruments, can only be settled by one keyed run of the probe below — a permission gate stopped this worker from reaching the key without printing it, and nothing was retried. What is already certain: on the Hub today VIX, DXY and US10Y are the only prices that never move during the day, because they come from a nightly FMP daily close while every equity comes from the Massive stream.

Yes, FMP streamsthe offer

Three socket clusters — stocks, forex, crypto. Login with the API key, subscribe by lowercase ticker, receive trades (T), top-of-book quotes (Q) and trade breaks (B). Stock cluster returns data 8 AM – 5 PM ET.

Unknown until keyedour entitlement

Sockets are entitlement-based per cluster, one simultaneous connection per cluster per account, and gated behind a one-time User Declaration Form. Our plan is at least Premium (the EOD history we already pull reaches 1962; only Premium/Ultimate carry 30+ years).

Reachable, protocol confirmedthe keyless test

Connection opened in 355 ms; login without a key answered 400 Bad Request; subscribe then answered 401 Unauthorized. The wire format matches the documentation exactly.

2 · The test, without ever printing the key

The probe reads FMP_API_KEY from the environment, scrubs every logged string against it, and prints one JSON summary: login status, message kinds, counts per symbol, latency from the message's own timestamp to receipt. It was run from the worker's machine without a key — that run is embedded below. A permission gate ([Credential Exploration]) blocked the worker's attempt to locate a non-printing path to the key; the attempt was not retried and no other route was tried.

4 · Design — “streams rule”, applied to the macro trio

The equities already obey one rule chain; the macro trio should join the same chain, not get a second one. Two branches, chosen by the keyed probe:

BranchWhenWhat is builtWhat the quotes contract shows
A · socketKeyed probe delivers messages for ^vix, ^tnx, dx-y.nybOne long-lived FMP stock-cluster connection, owned by exactly one process (the account allows one per cluster), subscribed to the three lowercase symbols, writing each T message into the same bounded-stream observation store the quotes handler already reads, tagged provider: FMP, price_surface: FMP_WS_BOUNDED_STREAM. Reconnect with backoff; resubscribe on reconnect; the existing daily FMP bar remains previous_close.Rule 1 TRADE_FRESH during 8 AM – 5 PM ET with price_age_ms under the 90 s bound; outside those hours the chain degrades honestly to rule 2/3 exactly as equities do after the close.
B · REST hydrationSocket is not entitled, or indices are silent on itA 60-second poll of FMP's REST quote for the three symbols (one call per minute — negligible against 750/min on Premium), written into the same store as a REST observation.Rule 2 TRADE_REST_HYDRATED with a one-minute age, still inside the bound, so the macro tiles move every minute and say how they were obtained.
  • Single owner. The suspended apps that once polled FMP or ran a market stream stay suspended; a second FMP socket from anywhere in the estate would be refused by the one-connection limit and would silently starve the first.
  • No new definition. /macro keeps the daily-close basis for anything settled (overlays, session logic). Only the live price surface changes.
  • Acceptance, measured not assumed: /quotes?symbols=VIX,DXY,US10Y returns state: OK, price_selection_rule 1 (branch A) or 2 (branch B), price_age_ms inside the bound during socket hours, previous_close still SETTLED from the FMP daily bar; the Hub rows stop saying NO STREAM; a real-browser screenshot of the three tiles moving across two reads.
  • Rollback: stop the owner process; the quotes handler falls back to NOT_OBSERVED_BY_STREAM and the Hub label returns to NO STREAM — the state it is in now.

5 · What this deliverable does not claim

  • It does not claim our key is entitled to sockets, nor that indices stream — the keyed probe decides both.
  • No code was deployed, no machine touched, no schedule changed, no key read, copied or printed.
  • Latency figures are absent on purpose: the keyless run cannot produce them.
