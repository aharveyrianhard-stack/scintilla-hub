I read both of them before touching anything: the older allocation module at allocation.scintillahub.ai (its source is _ALLOC_DEPLOY on this Mac) and the sector rotation tool (SECTOR_ROTATION.html, which publishes the table sector_rankings).

The sector rotation tool is a different animal: it computes RS-Ratio and RS-Momentum on weekly bars and puts each sector in Leading, Improving, Weakening or Lagging. It publishes a rank per sector, which is the thing worth borrowing.

WHAT I TOOK FROM IT, AND WHAT I LEFT Taken: counts at every stage, a reason attached to every removal, names kept visible after they are removed, a cap the page admits to out loud, and the stance that the page hands you a shortlist rather than a verdict. Left for later: the drop and pick buttons that remember your choices, and the comparables sheet. Those are interactions with saved state, and I would rather build them once, properly, than bolt them on tonight.

2 · THE PAGE NOW READS AS THE DECISION

Top to bottom: how much to own, where it goes, which names, why not the others, and then the picks. Layers one and two each carry a strip saying what it read and what it produced, so there is no step where a number appears without a source.

6 · WHAT COULD BE WRONG

  • The Geiger step is a sector line, not a zero line. In a weak sector a name can clear it while its own reading is still negative — today AT&T and Alphabet both do, in a sector whose middle is −0.34. The page now says so on the name's own line, and the slider lets you demand a positive reading instead.
  • The tape is read for sixty names, not all of them. Reading 120 daily bars for every name would be hundreds of requests. The names past that cap are listed as unread rather than dropped quietly, and the cap is a slider.
  • “Distance from a level” means distance from the 50-day average, not from a support or a base you would draw by eye. It is the honest version of the idea, not the full one.
  • Trend and distance read the same average, so they are not independent tests.
  • The debt figure is the last full financial year — it can be nine months old. The book date is printed beside every name it removes.
  • The rotation rank is a day old (published 22 September, read 23 September). The date is on screen, and the page says what that leg changed.
  • Per-timeframe Geiger is not available. The chart API publishes one composite per name across the eight rungs, not a value per rung per name. So the funnel uses the composite. I did not invent a per-timeframe number to fill the gap.
  • Three names per sector regardless of the sector's weight. Communications carries 6% today and still takes three names at 0.9% each. That is your perSector slider's doing, and it may want a rule.
  • Two greys on this page sit outside the house rule (the ink tones inherited from the page as it was built this morning). I left the palette alone rather than restyle a page you said you liked.

7 · WHAT I DID NOT DO

  • I did not push and did not deploy. The branch is local, and you merge it.
  • I did not change how much to own or how the sector weights are worked out, beyond adding the rotation leg at 25% — and the page states what that leg changed, so it can be set to 0 and checked.
  • I did not build the drop and pick buttons with saved state. That is the one piece of the other tool I would add next.
  • I did not touch the Indicator Lab, the prototypes index, or any other room.
  • I did not compute a Geiger, an RSI or any indicator of my own. Every reading on the page is one the chart API already publishes.
  • I could not test this against the live Hub origin: the chart API only accepts requests from scintillahub.ai, so for these screenshots I served the page locally and passed the API calls through a local proxy. The data in every screenshot is real and live — only the route to it was local.
