24 September 2026 · prepared for a closed-market window · nothing here was deployed, pushed or written to any database

Two attempts this morning admitted the 56 new names and had to be rolled back. The second one got as far as the board before the settled close refused the whole set over FINX, whose daily close said 25.4279 while the last official print said 25.42 — eight tenths of a cent. This unit does four things: it makes a cent a note instead of a refusal, it adds the check that asks the question before the window, it measures what the new names actually have on the Hub (very little, and that is the important finding), and it writes the order to switch them on.

1 · The cent rule

In the settled close, three independent numbers for the same close had to match to the last decimal: the daily aggregate, the previous-close surface, and the official closing print. Any difference at all refused the name — and one refused name refuses the whole day.

Now: a difference of one cent or less, or 0.05% or less, is admitted with a named note (CROSS_CHECK_WITHIN_TOLERANCE) that keeps all three numbers, the gap in dollars and the gap in percent. The number that enters the artifact is always the daily aggregate — nothing is averaged and nothing is picked as the "best" of three. Anything wider still refuses, exactly as before, and the refusal now says how far apart the sources were.

One deliberate difference from the brief. The brief said "$0.01 or 0.05%". On a $767 name 0.05% is 38 cents, and that would have re-admitted the measured 19 August defect — a mid-session snapshot of 767.71 standing in for a settled 767.45 — which two shipped tests exist to refuse. So the percentage leg is capped at five cents. FINX passes on the cent leg alone and never needed the percentage one. To get the uncapped rule the brief describes, set CROSS_CHECK_REL_MAX_ABS = Infinity: one line, nothing else changes. That is your call, and it is the first decision below.

I also checked what the Geiger machine really runs, rather than assuming. It injects exactly two files at every boot — settled-close-supervisor.mjs and boot-geiger.sh — and I verified both against the machine config: byte-identical to b20ee49. The one-shot is not injected, and neither is the file the cent rule lives in, so the tolerance ships with the image and needs no --file-local. The 420-name boot file still does.

4 · The preflight

Both failed attempts found out what the settled close thought after the board had been switched over. The preflight asks first. By default it reads the provider, builds the artifact in memory and writes absolutely nothing — no object, no candidate, no pointer, no database row. With --write-candidate it hands the job to the shipped one-shot, which can only write inside the candidate namespace and can never write the pointer.

# on the Geiger machine, read-only, writes nothing:
node services/stocks-ops/settled-close-preflight.mjs \
  --universe control/CANONICAL_EQUITY_UNIVERSE_20260820.json \
  --session <the last completed session>

# it prints, among other things:
#   "exception_count": 0,
#   "drop_from_set": [],                       <- every name here must leave the set
#   "CROSS_CHECK_WITHIN_TOLERANCE_count": 1,   <- FINX, with all three numbers kept

I could not run it against the real provider: the provider key and the R2 credentials are not on this Mac, and I do not extract credentials. What I did instead was run it against stubbed provider responses carrying FINX's real numbers — it admits FINX with the note, names a genuinely broken name and lists it for removal, and treats a provider-empty day as a named absence. The command above is the one to run in the window, before anything is admitted.

7 · What could be wrong

  • The preflight has not run against the real provider. Everything about FINX here rests on this morning's numbers and on stubs carrying them. If another name has drifted since, the preflight will say so — which is exactly why it runs first.
  • The FMP loaders are an inference. I could not read their source on this Mac. If they walk a list of their own rather than the tickers table, the new names will have prices and Geiger and still no financials the next morning, and someone has to add them to that list.
  • The funds land on the THEMATIC tab. 23 of the new names are funds. The taxonomy's own group is not one of the Hub's tabs, and the tickers table has no row without a cohort, so I put them in THEMATIC. It is visible, it is one UPDATE to change, and it is Alan's call.
  • The five-cent cap is my judgement, not the brief's. It is one constant.
  • Nothing here was run against production. No deploy, no machine change, no database write, no push. Every branch is local and every number above came from a read.
  • Two Hub tests and one Station-adjacent test fail before I touch anything (the age-function test, xfeed-publish, and indicator-lab-methods). They fail identically at the base commit.
