# Proposed house rule for `handoffs/BRIEF-20261002-AGENT-COMMON.md` (replaces the one-line 3 Oct entry)

- **No new rule without its neighbours (Alan, 3 Oct 2026: "something always new from one new rule bites us later"; made a procedure 5 Oct after BRK-B).** A rule is any guard, refusal, floor, retry, hold, schedule, backfill, spelling or format a service enforces. Before you add or change one:
  1. **Name its neighbours.** List every rule that reads the same input, writes the same output or runs in the same window (the universe file, the pins, the digest, the boot, the publisher, the previous-close robot, readiness). Write them in the commit message and the runbook under "The neighbours".
  2. **Test them together.** One test file exercises the new rule WITH each neighbour (a name failing while the others publish; the file missing while the boot continues; the map absent while the robot still answers). A rule tested alone is not tested. Public pattern: Kubernetes requires a probe AND a budget before a rollout; Argo Rollouts runs the analysis against the canary, not the old pod.
  3. **Prefer a maintained public pattern, cited, over an invention.** Say which project does it this way (LEAN, zipline, NautilusTrader, OpenFIGI, Prometheus, healthchecks.io, dbt, Pact, Argo). If none does, say so and why ours must differ.
  4. **A refusal is a mark, not a hold, unless Alan says otherwise.** The robot publishes what it has and NAMES what it refused (`cause`, `marks`, `universe_file`, `liveness`); the Hub shows the age and the names. Holding the board is the exception that needs his word (G1, 3 Oct).
  5. **Every rule has a switch and a record.** An env var or flag turns it off without a deploy (kill switch; LaunchDarkly/Unleash practice, and our `SETTLED_HOLD_DISPUTED=0`, `GEIGER_PUBLISH_PARTIAL`); a short decision record (what, why, follows, neighbours, rollback) sits in `runbooks/` or `DECISIONS.md` (the ADR practice: Nygard, adr.github.io).
  6. **A canary before, a smoke after.** `node scripts/smoke-after-deploy.mjs --base <throw-away machine> --mode canary` must be GREEN before the deploy and `node scripts/smoke-after-deploy.mjs` GREEN after it; a RED line is the rollback reason.
  7. **Contracts, not assumptions, between services.** A field one service reads from another is stated in `tests/contracts/payload-schemas.mjs` and checked on both sides (Pact practice). A spelling is never typed in a service: it comes from `services/identity/instrument-map.mjs`.
