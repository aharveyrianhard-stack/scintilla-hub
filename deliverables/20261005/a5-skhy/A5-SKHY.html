What the read-in found — the plan as written did not match what is running

  1. Tuesday's previous-close file is already final, and it is built on 590 names. The robot that builds it decides by "does the file exist and is it confirmed" and never checks which list of names it was built for. After a move to 591 the price service would reject that file, and the % column would be blank for every stock for the whole session — with nothing set to repair it. The fix inside a sitting is one extra step: rebuild that file on the 591 list by hand, right before the price service moves. The lasting fix is a small rule change that needs its own tests.
  2. On a weekday evening the visible steps belong just after midnight New York time, not at 20:30. Before midnight the board is still bound to today's file, which cannot be rebuilt for a new list. The preparation runbook already said this; tonight's instruction did not.
  3. The price-bar service and the hourly refresh run a newer version than the instruction named (the New York-clock fix from this afternoon), and the off-Hub scanners run another. An image cut from the named line would have silently removed both. The A5 branch now carries all three, so one image from it is safe.
  4. The Geiger machine carries 17 hand-placed files, not 18 or 8. All 17 match the reviewed code line byte for byte.
  5. The off-Hub scanners no longer need moving — since this afternoon they read the list of names at run time.
  6. The "is Tuesday's file published" gate cannot be read from the health page before midnight; it only reports the session in force. I read the file itself instead.
  7. The hourly refresh takes a two-hour lock after 20:15, and updating a sleeping scheduled machine starts it. It has to be moved only after its night pass has ended.
