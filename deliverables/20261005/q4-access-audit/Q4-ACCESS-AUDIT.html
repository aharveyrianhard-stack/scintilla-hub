The three biggest risks

  1. The database will send a web request for anyone. The job relay function accepts the address, headers and body from the caller and runs with the owner's rights; the public key may call it. Fix 1 closes it and breaks nothing found.
  2. The Hub's universe has a side door. tickers is protected, but three plain views onto it (cohorts, all_tickers, v_fundamentals_universe) accept writes from the public key and pass them through. Fix 2 makes views read-only and breaks nothing found.
  3. 74 tables have no rules and full public write — among them the daily Geiger history (14,737 rows), the market calendar, sector rankings, the pipeline's queues, and the Urth client and supplier details (names, addresses, emails). Fixes 3 and 4 switch rules on and keep every read as it is.

No table that holds a key is open: kv_secrets, app_config and app_settings all refused the public key. A scan of 224 publicly readable tables for key-shaped text found only the public key itself (inside two stored pages) and three chance matches inside two multi-megabyte terrain files.

1

The job relay — the database will send a web request for anyone

WRITE-OPENa function, not a table
What it is for
The scheduled jobs use one database function (scin_dispatch) to call the edge functions. It runs with the database owner's rights and takes the address, the headers and the body from whoever calls it.
Who writes it
Meant for: the scheduler only (1 scheduled job names it directly; the others go through it). Today: anyone holding the public key — the key that ships inside the Hub page — can call it and have the database send a GET or POST to any address, and each call adds a line to the job log. Two helpers (scin_record, scin_dispatch_reap) are open the same way.
Who reads it
No page.
What breaks if closed
Nothing found. Jobs run as the owner; edge functions use the service key. No Hub, Station or provider page calls it.
The change
01_close_job_relay_function.sql — take "execute" away from the public key and signed-up users.

Not tested by calling it (that would be a write). The finding is the function's own text plus its permission list, both read from the catalog.

2

cohorts · all_tickers · v_fundamentals_universe — a side door into the Hub's universe

WRITE-OPENthrough a view
What it is for
tickers is the list of what the Hub covers and which cohort each name sits in (613 rows est.). The table itself is protected. These three views are simple windows onto it — and the public key was given insert / update / delete on the views.
Who writes it
Meant for: jobs. Today: a write sent to the view passes through into tickers with the owner's rights, so the table's own rules do not apply. Anyone with the public key could move a name to another cohort, add one or remove one. The same pattern opens coldstore_current (the archive register) and four more: stream_health, ts_chart_lines_current, ts_chart_pivots_current.
Who reads it
Hub page and Station read cohorts, ticker_cohorts and all_tickers — reads stay.
What breaks if closed
Nothing found. No page writes a view.
The change
02_views_read_only_for_the_public_key.sql — views become read-only for the public key (35 views lose write grants; 7 of them were really writable).

Not tested by writing. The catalog says each of these is "automatically updatable", is owned by the owner role and is not marked to use the caller's rights.

Also open, outside the tables

  • Storage. All 5 buckets are public to read (audio 14, forms 0, hub 1, inbox 21, site 1,496 files). In inbox anyone may also upload and delete.
  • Functions. 160 of 181 database functions can be run with the public key. Most run with the caller's own rights, so they can only touch what the tables above already allow — once the tables are closed, so are they. 21 run with the owner's rights; fixes 1 and 6 cover them.
  • Signing up. A trigger confirms every new account at once, and 88 tables accept writes from any signed-in account. Whether sign-up is switched on could not be read from here (see below). There are 2 accounts today, none new in 30 days.
  • The ibkr area is also reachable with the public key: 4 of its 6 tables are readable (bars, quotes, collector health, an archived symbol map), none writable.
  • Views read past the rules. 37 of the 45 views and stored views show their table with the owner's rights, so a table can be private while its view is public. PAGE SPECS

What this page shows. Every table and view the public key can reach (the public area, 334 of them, plus the 6 in ibkr), whether access rules are switched on, what the public key can do, and who reads it.

Where each number comes from. "Rules on/off", the rule count and the grants come from the database catalog, read today. "Public key reads" is a real test: one row asked for with the public key, per table (308 answered, 32 refused; 2 answered with nothing because a rule lets no row through — counted as private). "Public key writes" is worked out from the grants and the rules — it was not tested, because a test would be a write. Row counts are exact where the table is open, estimates ("est") elsewhere. "Read by" is a search of the Hub page, the Hub's other pages and the Station code for the table's name. The June figure of 25 is the one quoted in the 17 June roadmap; that count was not re-derived.

Letters in the grants column. S read · I add · U change · D delete. A grant is only the first gate; with rules on, a rule must also allow it.

What could be wrong. A page that builds a table name at run time, or a tool outside the three code lines searched (the Indicator Lab, the Urth tools, scripts on other machines), would not show under "read by" — so an UNUSED-OPEN table may have a reader this audit could not see, and "breaks: nothing found" means nothing found in that code. What each rule-less table is for was read from its name and columns. 16 tables have rules on and no rule written: those are closed to the public key, which is correct.

What was not done. No write of any kind. No sign-in settings, request logs or storage listing were read. The functions were read, never called. The Urth tools were not audited.
